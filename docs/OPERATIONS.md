# 운영 — 자동화와 알림

## 실행 구조

**깃허브 Actions 가 서버다.** 사용자 PC 와 무관하게 돌아간다.

```
매일 22:00 UTC (한국 07:00) + 수동 트리거
  1. signal_check.py        수집 → 정제 → 주간 매수 판정
  2. holding_returns.py     보유기간별 수익률 갱신
  3. signal_probability.py  주중 신호 확률 (이 스텝이 직접 출력한다)
  4. position_tracker.py    전 구간 재생 → 포지션·동작 확정
  5. trend_compare.py       지금 흐름 vs 과거 신호 이후 (continue-on-error)
  6. data/ 자동 커밋
  7. 알림 발송
```

> 5번만 `continue-on-error: true` 다. 화면용 보조 모듈이라
> **여기서 죽어도 알림은 나가야 한다.** 대신 신호 집합에 의존하므로
> `signal_check.py` 뒤에 두고, 신호 건수를 재현 못 하면 스스로 죽는다.

> Actions 의 cron 은 정시에 뜨지 않는다. 30~60분 밀리는 것이 정상이다.
> 실측 22:48 UTC. 그래서 실제 실행 시각을 로그와 알림에 남긴다.

> 60일간 저장소 활동이 없으면 예약 실행이 자동 해제된다.
> 봇이 매일 data/ 를 커밋하므로 활동이 끊기지 않는다.

## 시간 (한국 기준)

| 단계 | 여름(EDT) | 겨울(EST) |
|---|---|---|
| 신호 확정 (금요일 미국 종가) | 토 05:00 | 토 06:00 |
| 알림 발송 | 토 07:00 | 토 07:00 |
| **진입** (월요일 미국 종가) | **화 05:00** | **화 06:00** |

미국장 운영시간: 여름 22:30~05:00, 겨울 23:30~06:00 (다음날).
**"월요일 종가"는 미국 시간이다. 한국시간으로는 화요일 새벽이다.**

## 알림

| 조건 | 경로 | 내용 |
|---|---|---|
| 매수 신호 | 텔레그램 + 이슈 | 순매수·문턱·주가·매도 규칙 안내 |
| 매도 신호 | 텔레그램 | 사유(RSI/상한)·진입일·수익률 |
| 새 데이터가 확인된 날 07:00 KST | 텔레그램 | 상태 요약 — 신호가 없어도 발송 |

점검 자체는 매일 실행한다. 다만 TSLA 종가 날짜와 ARK 보유 데이터 날짜가 직전
실행과 모두 같으면 텔레그램을 보내지 않는다. 따라서 새 데이터가 없는 일요일·월요일
아침에는 보통 알림이 오지 않는다. 수동 `force_heartbeat` 실행은 점검을 위해 예외로 보낸다.

### 토큰 취급

`TELEGRAM_TOKEN` / `TELEGRAM_CHAT_ID` 는 **GitHub Secrets** 에 있다.
- 레포 파일에는 없다(검증 완료: 작업트리·git 히스토리·원격 검색 전부 0건)
- 로그에서 `***` 로 마스킹된다(실측: 토큰 원문 0회, 마스킹 6회)
- 저장소가 퍼블릭이어도 안전하다

이슈에는 **담당자를 지정**한다. 레포 Watch 구독만 믿으면 알림이 조용히 안 갈 수 있다.

## 화면

**https://go2god4u-glitch.github.io/ark-tsla-signal/**

새로고침 버튼이 있는 상태 페이지. 매일 갱신된다.
게시용 정적 아티팩트는 데이터가 파일에 박혀 있어 새로고침이 불가능하므로,
같은 출처에서 `fetch` 할 수 있는 Pages 로 올렸다.

> Pages 와 CDN 이 JSON 을 캐시한다. `no-store` 만으로는 부족해
> 쿼리스트링에 타임스탬프를 붙인다.

## 점검 방법

```bash
gh workflow run signal.yml -f force_issue=true      # 이슈+텔레그램 매수 알림 경로
gh workflow run signal.yml -f force_heartbeat=true  # 상태 알림 경로
```

신호가 OFF 일 때는 알림 스텝이 skip 되므로, 정작 필요할 때 동작하는지
확인할 방법이 없다. 그래서 수동 점검용 입력을 뒀다.

## 워크플로 수정 시 주의

- **pyyaml 은 중복 키를 허용한다**(마지막 값으로 덮어씀). 깃허브 파서는 거부한다.
  검증기에 중복 키 검사를 넣어야 한다.
- **여러 줄 문자열을 YAML 블록 스칼라에 직접 쓰면 들여쓰기가 깨진다.**
  `printf` 로 한 줄씩 조립한다.
- **스텝 순서에 주의.** `signal_check` 가 확률 파일을 읽게 했더니
  `signal_probability` 가 그 뒤에 돌아 하루 전 값이 나갔다.
  값을 만드는 스텝이 직접 출력하게 한다.
- **출력 필드를 바꾸면 알림·화면도 같이 고쳐야 한다.** 포지션 모델을 바꾸면서
  워크플로가 옛 필드를 참조해 알림이 빈 값으로 나갈 뻔했다.
